# Step 7.1 — consumer enforcement: Tier 1 core (`Can()` + sudo bypass)

**Repos:** keeper, ant, squirrel, camel (repeat once per service, per protected entity)
**Needs sign-off:** no
**Depends on:** step 6 (local policy cache must exist)

## What

The `Can()` gate, resolved from JWT + the local cache from step 6 — no record is fetched then rejected after the fact.

```go
func Can(user User, service string, appID int, resource, action, field string) bool {
    assignments := userRoleAssignments(user, service) // global (service_id NULL) + this service's roles

    for _, a := range assignments {
        if !a.IsSudo {
            continue
        }
        if a.AppID == nil || *a.AppID == appID {
            return true // sudo gate passed AND tenant scope gate passed
        }
    }
    for _, a := range assignments {
        if hasPermission(a.Role, resource, action, field) {
            return true // non-sudo permission match; tenant isolation already enforced via jwt.app_id
        }
    }
    return false
}
```

Multiple roles for the same user in one service: union the permission sets of all assigned roles at check time (still a flat lookup, no graph traversal — no role hierarchy in this plan).

This step only covers the coarse CRUD check — call `Can()` with the base action (e.g. `order.update`), ignoring field/scope for now. Tier 2 (field-level, step 7.2) and Tier 3 (ownership, step 7.3) layer on top once this lands.

## How (per protected entity, per service)

1. Add `Can()` and `userRoleAssignments()` to the service's policy-consuming package (reads `Policies(ctx)` from step 6's `Store`).
2. Add a middleware or handler-level helper wrapping `Can()` — call it before the entity's business logic runs, for every mutating and read endpoint.
3. Sudo assignments with `app_id` set still get queries scoped to that one app (tenant isolation and sudo bypass are orthogonal gates — both must pass; sudo only skips the *permission* check, not tenant scoping already enforced via `jwt.app_id`).
4. Replace existing hardcoded role checks (e.g. `claims.IsSysAdmin()`, `claims.IsManager()`) with `Can()` calls one entity at a time — do not leave both in place long-term, but land per-entity so each diff stays reviewable.
